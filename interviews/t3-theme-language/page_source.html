Already decided

Themes are a CSS-syntax subset addressed to the named anatomy (::part(), :state(), stable IDs), not a document tree. No combinators. No layout properties. Inheritance only for text and colour roles. Engine inputs are custom properties only the engine sets. Expressions are T2's bounded grammar. New effects are C++ engine primitives, never theme code. Shape is an engine parameter; themes never set geometry or hit regions. Images are named resources (CNG native, PNG for interchange). Themes are data only, may be swapped live, and need a content hash, not a signature. Names are kebab-case. Form documents share this syntax and parser. An untouched file round-trips byte for byte.

The engine side is built: T2's rules, cascade, primitives and CSS coverage table (planning/stages/T2-engine-core/CSS_COVERAGE.md). Its blueprint is sealed; its optimisation and full population continue alongside T3.
